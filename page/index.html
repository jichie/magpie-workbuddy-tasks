WorkBuddy 任务

批量自动化 · 本地守护进程

把 WorkBuddy 国内版的成长任务做成批量流水线：批量接取、点亮（上报进度）、领奖， 外加猫猫旅行与夜猫子任务，按小时窗口自动排程（默认成长/旅行 09:00 · 21:00，夜猫子 01:00）。 全程遵守风控节奏：任意两次上游调用至少间隔 1 秒，账号之间 1.5–5 秒。

用哪些账号：复用 magpie 已登录的 WorkBuddy（国内版）OAuth 个人账号； API key 账号与企业账号不参与。本入口卡没有读取权限（插件 permissions 为空）， 账号列表、任务进度与快照都在看板里查看。access/refresh token 永不出守护进程。

看板地址

http://127.0.0.1:4390 在新窗口打开看板

地址来自插件选项 dashboardUrl（magpie 插件页可改）。看板直接打开即可， 全部接口无鉴权，靠网络边界保护 —— 守护进程默认只绑 127.0.0.1；改成 0.0.0.0 后局域网内任何人都能触发批量任务或导出含凭据的文件， 不用时请关闭端口转发。

magpie 跑在 NAS/容器里、你用 SSH 隧道访问？隧道映射后仍可用 127.0.0.1:4390 打开看板，无需改 dashboardUrl。

状态说明

如何启用 / 停用

守护进程跟随 magpie：在 magpie 插件管理里开启本插件即自动拉起 （写 control.json desired=on），关闭插件即优雅退出 （desired=off）。看板顶栏也有「停止守护进程」按钮（POST /api/shutdown）； 浏览器无法启动本机进程，需要手动拉起时在插件目录执行 node daemon.mjs。

Docker / NAS 部署怎么打开看板

守护进程默认只绑 127.0.0.1；容器里需要对外时用选项 listenAddress 或 --addr 绑 0.0.0.0。此时看板仅容器网桥/局域网可达， 请用 SSH 隧道或局域网地址访问，切勿发布到公网（0.0.0.0 是监听值，不是可打开的地址）。

查容器 IP：docker inspect -f "{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}" magpie； 建隧道：ssh -L <port>:<容器IP>:<port> <user>@<NAS地址>， 映射后仍可用 http://127.0.0.1:<port>/ 打开。实际端口与绑定 host 由守护进程写在 state/daemon.json；看板页面不再显示访问地址，需要时直接看该文件里的 host 与 port。 看板无鉴权：改绑 0.0.0.0 期间请用防火墙/隧道限制来源，不用时关闭端口转发。

为什么这里看不到实时数据

本页运行在 magpie 的沙箱 iframe 里（sandbox="allow-scripts"， CSP connect-src 'none'）：不允许 fetch / WebSocket，也没有申报任何 magpie.read 权限，所以无法请求守护进程的 /api/state 或 SSE。 这是一张诚实的入口卡 —— 账号、14+ 项成长任务表、批量操作、实时步骤/日志、排程与历史， 全部在独立看板里（同源静态页，由守护进程服务）。

看板里能做什么

勾选账号 →「批量接任务」（只接取，不点亮；只提交守护进程判定 canAccept 的任务， 自动任务与桌面端 / 未收录任务不进名单，不可自动接取的项数在按钮旁说明）、 「批量做任务」（接取 → 点亮 → 领奖完整流水线）、 「只领奖」（补领「待领奖」）、「每日签到」（连登）；自动 / 手动领奖两种模式； 每个账号可单独开关「参与任务」（关闭后批量与排程都会跳过它）； 单账号任务表可逐项接取 / 领奖、查看进度与奖励（积分 / 能量），并按守护进程下发的 判断字段标注「需在桌面端完成」「无法自动化」（附原因原文）与钉死的专家 id （ex_…）—— 前端不自己猜，判断只来自后端； 风控冷却（403/11140）名单直接显示解除时间； 实时步骤与滚动日志走 SSE，断线自动回退 3 秒轮询；小时窗口排程可编辑并预览下一次运行； 历史记录失败 / 跳过都会留一行说明； 账号导入 / 导出：导出为 hub 同款 workbuddy-accounts JSON （默认含凭据，可改脱敏），导入走「先预览（只读、不写盘）→ 确认写入 plugin-auth.json（写前自动备份）」两段式，只同步国内版、智能合并， 不删除任何现有账号。
